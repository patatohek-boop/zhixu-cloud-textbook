## 从教学程序走向工程软件

本节把前面的方法对应到实际软件文件，并给出可复核的交付结构。软件版本属于实验条件：同名模型、字典字段和求解器在不同发行版中可能不同。

以下命令仅针对  **OpenFOAM Foundation 13**  的官方后向台阶教程，依据该版本文档核对。它是 **等温流动练习** ，用于熟悉网格、边界、湍流、求解和后处理；不是前面三个换热案例的现成求解文件。本次教材制作未在本地执行 OpenFOAM，因此不提供伪造的运行日志或宣称通过的 CFD 结果。

## 一、先认识案例的三个目录

|目录|它回答的问题|检查内容|
|---|---|---|
|`0`|初始场和边界是什么？|速度、压力、湍流变量及每个 patch 的条件|
|`constant`|几何及物理模型是什么？|网格、物性、输运与湍流模型|
|`system`|如何离散和求解？|网格生成、格式、线性求解器、算法和写出控制|

`0` 的名字不保证其所有字段都是实际物理初值：稳态迭代需要初始猜测。`system/fvSchemes` 决定离散表达，`system/fvSolution` 决定代数求解及算法控制；改变容差不会自动提高空间离散阶数。

## 二、完成一个可重复的等温入门案例

前提是在 Linux 或已配置好的 WSL 环境中安装并加载 Foundation 13。以下是在该环境的 shell 中执行，不是在 Windows PowerShell 中直接粘贴。先用 `foamVersion` 核对版本；不匹配时查对应版本文档，不猜目录名称。

```bash
foamVersion
# 确认显示 Foundation 13，并且环境变量已经由该版本配置。
test -n "$FOAM_RUN" && test -n "$FOAM_TUTORIALS" || exit 1
mkdir -p "$FOAM_RUN"
cd "$FOAM_RUN" || exit 1
test ! -e zhixu-step-13 || { echo "目录已存在，请另取案例名"; exit 1; }
cp -r "$FOAM_TUTORIALS/incompressibleFluid/pitzDailySteady" zhixu-step-13
cd zhixu-step-13 || exit 1
blockMesh > log.blockMesh 2>&1 || exit 1
checkMesh > log.checkMesh 2>&1 || exit 1
foamRun > log.foamRun 2>&1 || exit 1
paraFoam
```

命令正常结束只是第一关。逐一查看日志中的网格质量、求解残差和守恒信息；停止于最大迭代次数不等于达到收敛。用 ParaView 查看壁面、入口与出口是否符合预期，再提取剖面和积分量，不能只看自动缩放色标。

这些命令运行的是你复制的官方案例；后续修改请另存新案例，保留基准。不要把上一轮产生的时间目录误认为新设置的结果。

## 三、把模型选项与方程对应起来

此版本案例在 `constant/momentumTransport` 中选择 RAS 模型。若换模型，需同时核对相应场、边界条件、离散格式、线性求解设置和近壁要求；只替换模型名称不构成完整的选型实验。

特别检查压力单位。若字段存储运动学压力 $p_k=p/\rho$，其单位是 m²/s²，物理压差为 $\Delta p=\rho\Delta p_k$。例如恒密度空气 $\rho=1.2$ kg/m³、计算压差 50 m²/s²，则物理压差 60 Pa。定义随求解器改变，必须从维度和文档确认，不能见到字段名 `p` 就默认 Pa。

## 四、进入换热与共轭传热时需要增加什么

从等温台阶转向 [加热圆管](#/course/fluid-mechanics/fluid-mechanics-57)，必须使用确实求解能量的合适求解器或模块，提供温度/焓的状态关系、热物性、热边界和对应的数值设置。向文件夹添加一个 `T` 文件，不会让不求解能量的程序自动产生正确温度场。

进入 [共轭散热案例](#/course/fluid-mechanics/fluid-mechanics-59)，还需分别建立流体和固体区域、区域物性及网格、守恒的界面耦合和多区域求解控制。自然对流还需重力、密度处理与开放边界；辐射需独立模型和适用的表面条件。

先在选定发行版的官方热传递示例上确认字段名称和最小可运行结构，然后逐项替换成前面案例的尺寸、材料和边界。Foundation 与 OpenCFD 的版本号、求解器组织方式及语法不同；本教材引用其他版本资料时会明确标注，不能混合复制。

## 五、提交一份别人能够复算的结果

建议每个算例保留以下结构，文本文件尽量记录单位：

```text
case-study/
  README.md            # 问题、假设、软件版本与复算步骤
  input-table.csv      # 尺寸、物性、边界及来源
  cases/               # 三套网格或独立参数工况
  logs/                # 网格、求解、环境版本
  postprocess/         # 提取温度、压降、热量的脚本
  results/             # 原始数值表和图
  validation.md        # 守恒、网格、时间步与实验对照
```

若网格或结果太大，不要强行全部提交普通 Git 历史。保存可重建脚本、输入和校验摘要，并明确大文件的存放位置及访问方式。记录提交号，使 AI 数据样本能追溯到产生它的物理与数值设置。

### 五项验收门槛

1. 方程和边界代表实际问题，且独立输入之间没有互相矛盾。
2. 网格质量和近壁解析满足所选模型，关键量对网格/时间步的变化已经报告。
3. 迭代、质量、能量和目标量共同达到预先约定的容差，而非只看一条残差。
4. 后处理有单位、平均定义、基准位置和误差说明。
5. 验证与实验确认分开记录，未测量或未验证的结论明确保留为假设。

## 覆盖范围与继续深造

本专项覆盖单相连续介质流动换热的主要工作链、常用湍流闭合和近壁处理。高 Mach 数热流、燃烧、沸腾冷凝、颗粒/多相、复杂辐射、流固结构耦合、伴随优化和高阶自适应方法需要后续专门课程；不能把本章的清单解释为已掌握所有 CFD 领域。

## 练习与解析

<details><summary>练习 1：修改湍流模型后程序读不到 omega，应该直接删除报错字段吗？</summary>

不应。先确认新模型需要的变量、维度、初边值和求解设置。缺少 omega 往往说明案例配置没有随模型一起更新。删除或填零来绕过报错可能破坏模型定义。
</details>

<details><summary>练习 2：两张温度云图颜色一样，能断言两个方案最高温度相同吗？</summary>

不能。自动色标可能各自重新缩放。应使用一致单位与色标，直接读取同一实体的最高温度，并报告位置、网格敏感性和统计方式。
</details>
