## 零基础入口：模拟考试时，连“尺子”也不能偷看新数据

假设一个特征的训练值为 10、14。我们想把数值变成“离训练中心多少个训练尺度”，便于后续模型计算。未来来了 22，应使用训练时确定的尺子，还是先把 22 加进去重新造尺子？如果每看到新题就重造规则，评价过程就不再模拟一个已经训练好的系统。

这里用四个数演示流程，不能把它们当成足够大的实际训练或测试集。先按预测任务确定独立单位和划分，再设训练值为 `[10,14]`、验证值为 `[18]`、测试值为 `[22]`。

### 完整手算：fit 与 transform 是两种操作

`fit` 意为从允许的数据中**估计规则的参数**；`transform` 意为按保存的规则**变换数据**。令 $\mu$ 为训练均值、$s$ 为训练尺度，本例明确使用分母为训练样本数 $n=2$ 的标准差，而非无偏方差估计的 $n-1$：

$$\mu=\frac{10+14}{2}=12,\quad
s=\sqrt{\frac{(10-12)^2+(14-12)^2}{2}}=2,\quad
z=\frac{x-\mu}{s}.$$

$x$ 是待变换的原数，$z$ 是变换后的无量纲数。训练数据变为 -1、1；验证的 18 变成 $(18-12)/2=3$；测试的 22 变成 5。新样本不落在 [-1,1] 中完全可能，这不是“必须重新标准化”的报错信号。

```python
train = [10.0, 14.0]
validation = [18.0]
test = [22.0]
mean_train = sum(train) / len(train)
variance_train = sum((x - mean_train) ** 2 for x in train) / len(train)
scale_train = variance_train ** 0.5

def transform(values):
    return [(x - mean_train) / scale_train for x in values]

print(transform(train))
print(transform(validation))
print(transform(test))
```

输出依次为 `[-1.0, 1.0]`、`[3.0]`、`[5.0]`。这里函数只读取已经保存的训练均值和尺度，调用时没有再次计算它们。示例已知尺度为正；实际流程必须规定零方差列怎么处理，并把变换参数与模型一同保存。

### 谁能参与哪种决定

训练集用于估计预处理和模型参数；验证集用于比较方案或选超参数；测试集用于评价已固定的最终方案。交叉验证时，每折都重新在该折的训练部分 `fit`，不是在全数据上先 `fit` 一次。方案选完后可以按预先规定在训练加验证数据上重训最终流程，但测试集仍不能参与拟合或选择。

常见误解：“没有看标签，所以不会泄露。”若上面先把四个输入合起来求均值，得到 16 而非 12，训练表示就已经依赖验证和测试输入。这不保证每次分数都会虚高，却违反独立评价的信息边界。官方例子与 Pipeline 用法见[scikit-learn：数据泄露](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)。

## 严格区分参数学习、方案选择和评价
**训练集**参与估计模型及预处理参数；**验证集**参与方案和超参数选择；**测试集**只评价已经固定的方案。

### 拟合与使用变换

`fit` 根据数据确定变换参数或模型参数；`transform` 按已经确定的规则变换输入，不重新估计。标准化就是先在训练数据估计位置和尺度，再把同一公式用于新样本。

**信息泄露**指训练或选择使用了真实预测时不会获得的信息。它包含“未来才生成的特征”，也包含“用测试集选择何时停止”。通俗地说，模拟考试时提前看答案，或者看过分数再改卷子，都使分数失去原本意义。

## 为什么独立测试有统计依据
设训练与选择全部结束后模型 f 已固定，测试点 $(X_i,Y_i)$ 独立同分布来自目标分布，并独立于全部选择过程。若损失期望存在，
$$E\!\left[\frac1m\sum_{i=1}^m\ell(Y_i,f(X_i))\mid f\right]=R(f),$$
其中 m 为测试样本数，$R(f)=E[\ell(Y,f(X))\mid f]$ 是该模型的目标风险。证明就是逐项取条件期望，每项都等于 R(f)，再除 m。



### 独立测试结论的边界

这说明正确划分有什么用，但并不保证某次有限测试分数恰等于真实风险。若反复按测试结果挑 f，条件独立前提失效，不能再引用这个证明。时间相关、同设备相关也会影响方差与代表性，必须以真正预测对象为独立单位。

标准化 `fit` 即使没读标签，也会利用输入分布。下文 [0,2] 与未来 100 的例子会把训练表示改变；后续各折必须重新拟合全部学习步骤，不能仅重新拟合最终模型。

## 测试集扮演未来
训练集用于学习参数，验证集用于选择超参数与方案，测试集用于最终估计泛化表现。三者角色不同，不是随意分成三堆即可。划分应模拟实际部署：若未来预测新设备，就按设备分组；若预测未来时刻，就按时间先后；若随机抽样的新样本独立同分布，才适合普通随机划分。

同一人的多张照片、同一实验的相邻切片、同一文章的改写版本可能高度相似。若跨训练与测试出现，模型可能识别个体或重复内容，而不是学会任务规律。先明确独立单位，再划分，往往比选复杂模型更重要。

## 泄露不仅来自标签列

<figure class="teaching-figure"><a href="assets/diagrams/ml-data-split-leakage.svg" target="_blank" rel="noopener" aria-label="打开大图：先划分数据，再只在训练部分拟合预处理与模型；验证集用于选择，测试集用于最终评估。"><img src="assets/diagrams/ml-data-split-leakage.svg" alt="先划分数据，再只在训练部分拟合预处理与模型；验证集用于选择，测试集用于最终评估。" loading="lazy"></a><figcaption>先划分数据，再只在训练部分拟合预处理与模型；验证集用于选择，测试集用于最终评估。<br><small>示意训练/验证/测试角色，不规定通用划分比例。时间或组相关数据需采用相应划分；交叉验证每折须重新拟合预处理。 · 点按图形可放大。</small></figcaption></figure>


泄露是训练或选择过程使用了真实预测时不可获得的信息。典型情况包括把未来测量当特征、用全数据均值填补缺失、在全数据上做特征筛选、重复查看测试集挑最佳模型。即使预处理没有直接使用标签，也可能让测试分布信息进入训练流程。

正确原则是：先划分，再只在训练部分 fit 预处理，随后对验证与测试 transform。交叉验证时每折都要重新拟合预处理。Pipeline 将变换与模型绑在一起，有助于维持这一规则，但不会自动识别所有时间或业务泄露。

## 逐步例题：标准化泄露
训练值为 [0,2]，测试值为 [100]。训练均值为 1，若只用训练数据，中心化后为 [-1,1]，测试变为 99。

### 对照：泄露如何改变训练表示

若先用全数据求均值 34，训练变为 [-34,-32]，表示训练过程已知道未来出现了极端值。结果偏差的方向依赖模型和数据，不能以“这次影响不大”合理化错误流程。

标准化常写成 $z=(x-\mu_{\mathrm{train}})/s_{\mathrm{train}}$。零方差列需特别处理；类别编码要考虑测试出现新类别；缺失值填补需要保存训练得到的规则。

### 部署复用同一变换

部署时必须使用同一套已拟合变换，而非对每批新数据重新学习。

## 样本量与版本
没有适用于所有任务的固定 80/20 比例。小数据需要兼顾训练效率与评估方差，可使用交叉验证；时间任务需要足够长的未来窗口；稀有类别需保证评估有足够事件。测试集应尽量独立封存，重大任务变化后可能需要新的评估集。

记录划分随机种子、分组键、时间界限和数据版本。若数据有重复或近重复，应在划分前定义去重策略，但不能利用未来标签做选择。测试集上的好结果只能支持与它代表的分布相近的应用情境。

## 防止目标定义悄悄泄露
设备维修后的记录、最终审核结论或事后汇总字段，可能与标签高度相关，却在预测时尚不存在。应按字段生成时间检查可用性，并让熟悉实际流程的人审阅。仅删除目标列不能保证特征没有包含目标的替代信息。
