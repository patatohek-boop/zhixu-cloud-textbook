## DataFrame、粒度、键与聚合
**DataFrame** 是带行索引与列标签的二维表格，不同列可有不同数据类型。**数据粒度**说明一行代表一次什么事件；**键**是一组用来识别或匹配记录的字段；**连接**枚举符合键相等条件的记录对；**聚合**把一组记录压缩为统计量，因此改变粒度。

### 索引并不保证唯一

DataFrame 的索引标签可以重复，存在索引并不自动保证记录唯一。

对某个键，左表有 a 行、右表有 b 行，则内连接产生 ab 个匹配对。这是乘法计数原理：左侧每一行都分别匹配右侧 b 行。故左连接也并非无条件保持原行数，右键重复时会扩张。例如同一设备在左表有两次观测，在右表有三条元数据，按设备键连接便得到六个记录对。

## 总体均值与组均值的关系
设第 k 组有效样本数为 $n_k>0$、均值为 $\bar x_k$，则全部观测均值为
$$\bar x=\frac{\sum_k n_k\bar x_k}{\sum_k n_k}.$$
证明：每组总和等于 $n_k\bar x_k$，把总和相加再除以总数量即得。以全部观测等权为目标时，一般应按有效组大小加权；各组大小相同时等价于直接平均组均值。若目标本来是每组等权，则直接平均回答的是那个不同问题。组大小不同不排除数值恰好相同，例如两组 [2] 和 [2, 2, 2] 的均值都为 2。

### 有效数量和总数量

缺失项不属于有效数量，但应另报总行数，避免掩盖删除后的样本组成。

`loc` 用标签、`iloc` 用位置；多个 Series 相加默认可能按标签对齐。

### 写入必须指向原表

pandas 3.0 起 Copy-on-Write 是默认且唯一模式，链式赋值不能可靠更新原表，应使用单次 `df.loc[mask, "col"] = value`；这不是单纯忽略一个警告即可修复的问题。[官方写入语义](https://pandas.pydata.org/docs/user_guide/copy_on_write.html)

## 例：观测记录与设备表连接
DataFrame 是带行索引与列标签的表格结构，各列可以拥有不同类型。开始分析前先回答：一行代表什么，哪几列组合应唯一，缺失意味着什么，数值单位是什么。若一行是一次观测，把它当成一台设备，就可能重复计数。工具越方便，越要先确认数据语义。

```python
import pandas as pd

observations = pd.DataFrame({
    "sensor": ["A", "A", "B"],
    "temp_c": [20.0, None, 24.0]
})
metadata = pd.DataFrame({"sensor": ["A", "B"], "room": ["北", "南"]})
joined = observations.merge(metadata, on="sensor", how="left", validate="many_to_one")
print(joined)
summary = joined.groupby("sensor")["temp_c"].agg(["count", "mean"])
print(summary)
print(observations["temp_c"].isna().sum())  # 1
```

mean 默认通常跳过缺失值，因此 A 的平均为 20，并不表示缺失值自动测得 20。

### 分清 count 与 size

count 统计非缺失值，size 统计行数，二者有不同含义。报告平均值时同时报告有效样本量，可以避免把一个观测与一百个观测看成同等可信。

## 选择与转换
loc 按标签和条件选择，iloc 按整数位置选择。筛选温度大于 21 可写 `df.loc[df["temp_c"] > 21]`。赋值时使用明确的单次 loc 选择，避免链式索引导致操作副本还是原表不清楚。读取 CSV 后应检查 dtypes，日期用明确格式解析，数值转换失败时要保留错误证据。

缺失处理没有万能答案。删除可能改变样本组成，填均值会压低方差，前向填充需要时间顺序和业务依据。

### 填补也有训练边界

对于机器学习，填补统计量只能从训练数据学习；先在全数据上填均值再切分会把测试信息带入训练过程。

## 连接类型与匹配数量

### 缺失键也需要明确规则

pandas 的 `merge` 会把两侧的缺失键互相匹配，不能照搬通常 SQL 中空值不匹配的直觉。设备编号缺失时，应先按记录契约拒绝或单独保留这些行，避免把不同的未知设备当成同一设备连接。[官方连接说明](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.merge.html)明确列出了这一差异。

`groupby` 默认 `dropna=True`，分组键缺失的行不进入结果；若业务要求保留缺失键这一组，可显式使用 `dropna=False`。这与温度列中缺失值是否参与 `mean` 是两项独立规则，检查总行数时不能混淆。[官方分组参数](https://pandas.pydata.org/docs/reference/api/pandas.DataFrame.groupby.html)给出了对应约定。

### 匹配数量与唯一性
如果左表某键出现两次，右表同键出现三次，多对多连接会产生六行。这不是软件故障，而是所有匹配组合的结果。应检查键唯一性，并使用 validate 声明预期关系。left 连接保证左表每条记录至少出现一次，但右键重复时可能扩增；inner 只保留两侧匹配键；连接方式会改变分析总体，不能仅凭“结果更整齐”选择。

聚合后粒度发生变化，例如从观测变成设备。图表、统计与模型都应跟随新粒度解释。不要把设备均值再不加权平均后当作所有观测的总体均值，除非每台设备样本数相同或目标本就要求设备等权。

## 有效数量、缺失与统计权重
假设设备 A 有一个读数十度，设备 B 有九个读数二十度。先求设备均值再等权平均得到十五度；对全部十次观测平均得到十九度。两者都可计算，但回答的问题不同：前者给设备等权，后者给观测等权。
因此报告应同时保留有效数量、总数量和缺失数量，说明目标总体。若采样频率不同，观测加权还可能让高频设备主导结论，需要根据任务选择时间或设备权重。
表格索引可以提高对齐便利性，也可能让看似按位置相加的操作实际按标签对齐。合并、赋值和算术后检查行数、键、缺失和汇总量，能发现很多静默错误。不要只查看前五行就认为整张表已经正确。

连接后核对行数与匹配关系，聚合后核对有效数量与分组含义。
