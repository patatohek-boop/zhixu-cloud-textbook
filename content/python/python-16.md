## 何时需要对象
当一组数据与一组操作始终一起出现时，类可以表达它们的共同概念。比如一个温度记录器既保存读数，又提供添加和平均操作。类是对象的构造规则，实例是按规则创建的具体对象。不是每个函数都需要放进类；无状态的简单计算使用函数通常更直接。

```python
class TemperatureSeries:
    def __init__(self, name):
        self.name = name
        self.values = []

    def add(self, value):
        self.values.append(float(value))

    def mean(self):
        if not self.values:
            raise ValueError("尚无读数")
        return sum(self.values) / len(self.values)

a = TemperatureSeries("A")
b = TemperatureSeries("B")
a.add(20)
a.add(22)
print(a.mean())   # 21.0
print(b.values)   # []
```

self 表示当前实例，调用 a.add(20) 时，a 会作为 self 传入。__init__ 初始化实例状态，不负责返回新对象。把 values 在 __init__ 中创建，可以让每个实例拥有独立列表；若误写成类体中的 values=[]，所有实例可能共享同一列表。

## 封装是维护不变量
封装不只是给属性加下划线，而是让对象始终满足重要约束。例如读数必须有限且单位一致，就应在 add 中校验，而不是期待所有调用者都自觉遵守。单下划线表示内部使用约定，并非不可突破的安全屏障。必要时用 property 提供受控访问，但不要为每个字段机械添加复杂访问器。

组合表示“有一个”：实验对象可以拥有多个传感器对象。继承表示“是一种”：子类应能在需要父类的地方保持契约。若子类改变了方法的基本含义，调用者可能被破坏，此时组合往往更合适。继承不是代码复用的唯一方式，更不是层次越深越专业。

## 方法、协议与多态
Python 常重视对象“能做什么”，例如可迭代对象只需满足迭代协议，不必继承某个具体业务父类。这种按行为合作的思路叫鸭子类型。__repr__ 提供调试表示，__len__ 支持 len，__iter__ 支持遍历；这些特殊方法应遵循对应协议，不要仅为了语法花哨而滥用。

对象设计仍需考虑测试：构造时避免自动联网或读取大量文件，让依赖可以传入。将核心计算与输入输出分离，能让对象在脚本、测试与界面中复用。本例为教学简化，add 还未验证 NaN 和绝对零度，实际项目应根据契约补齐。

## 通过职责判断是否建类
先列对象必须保持的状态，再列改变这些状态的合法操作。如果数据只进入函数、计算一次就返回，没有需要共同维护的长期状态，普通函数可能更清楚。如果多个操作需要共享同一组约束，类的价值就更明显。
继承层次应保持可替换性。例如子类方法若突然不再接受父类允许的输入，使用父类接口的调用者就可能失败。复用几行代码不足以证明存在合理继承关系，组合往往更容易控制变化。
对象也可能造成隐藏耦合：一个方法修改状态，另一个方法依赖调用顺序，却没有文档说明。可以让方法名表达副作用，提供明确初始化流程，并通过测试覆盖状态转换。面向对象的目标是让变化可理解，不是把所有名词都变成类。

## 练习
1. 若 values=[] 写在类体中，两个记录器可能出现什么问题？
<details><summary>查看解析</summary>它成为类属性，实例可能共享同一可变列表，一个记录器添加数据会影响另一个。应在 __init__ 中为每个实例创建列表。</details>

2. “实验包含传感器”适合继承还是组合？
<details><summary>查看解析</summary>适合组合。实验不是一种传感器，而是持有传感器的对象，二者职责和语义不同。</details>
