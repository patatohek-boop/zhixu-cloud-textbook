## 对象不是只有数据的字典
**类**定义一类实例共享的行为与构造规则；**实例属性**保存在某个实例的状态中；**类属性**由类提供，实例找不到同名属性时可访问它。**实例方法**被调用时会接收当前实例作为第一个参数，通常命名为 `self`。`a.add(20)` 的行为可理解为调用该类的方法并把 a 作为 self。

**实例不变量**是对象在公开操作之间应满足的性质，例如“每个温度值有限且不低于绝对零度”。封装的目的在于让构造与每个修改方法保持这些性质，单纯使用下划线不能提供密码式访问保护。

## 独立状态为何需要在初始化中创建
构造 a 时执行一次 `self.values = []`，得到列表 A；构造 b 时再执行一次，得到列表 B。A 与 B 身份不同，所以 a.add 不改变 B。若 `values=[]` 放在类体中，该表达式只在定义类时执行一次，两个没有覆盖该属性的实例会共享它。这一论证依赖对象创建次数，与变量名字叫 a 还是 b 无关。

通俗地说，类是说明书，每台仪器仍应有自己的记录本，不能把说明书附带的同一本记录本交给所有仪器一起写。下文示例为教学最小版本，添加读数时还需由调用者提供有效有限温度；若把验证加入 `add`，应先验证再追加，失败时保持旧状态不变。

## 何时需要对象
当一组数据与一组操作始终一起出现时，类可以表达它们的共同概念。比如一个温度记录器既保存读数，又提供添加和平均操作。类是对象的构造规则，实例是按规则创建的具体对象。不是每个函数都需要放进类；无状态的简单计算使用函数通常更直接。

```python
class TemperatureSeries:
    def __init__(self, name):
        self.name = name
        self.values = []

    def add(self, value):
        self.values.append(float(value))

    def mean(self):
        if not self.values:
            raise ValueError("尚无读数")
        return sum(self.values) / len(self.values)

a = TemperatureSeries("A")
b = TemperatureSeries("B")
a.add(20)
a.add(22)
print(a.mean())   # 21.0
print(b.values)   # []
```

self 表示当前实例，调用 a.add(20) 时，a 会作为 self 传入。__init__ 初始化实例状态，不负责返回新对象。把 values 在 __init__ 中创建，可以让每个实例拥有独立列表；若误写成类体中的 values=[]，所有实例可能共享同一列表。

## 封装是维护不变量
封装不只是给属性加下划线，而是让对象始终满足重要约束。例如读数必须有限且单位一致，就应在 add 中校验，而不是期待所有调用者都自觉遵守。单下划线表示内部使用约定，并非不可突破的安全屏障。必要时用 property 提供受控访问，但不要为每个字段机械添加复杂访问器。

组合表示“有一个”：实验对象可以拥有多个传感器对象。继承表示“是一种”：子类应能在需要父类的地方保持契约。若子类改变了方法的基本含义，调用者可能被破坏，此时组合往往更合适。继承不是代码复用的唯一方式，更不是层次越深越专业。

## 继承、重写与 super 的实际执行
`class Child(Parent)` 定义子类；**重写**指子类提供同名方法。调用 `obj.method()` 时按对象实际类型寻找实现，这让相同调用支持不同对象行为，称为多态。`super()` 按当前类之后的方法解析顺序继续寻找，单继承时通常进入父类；多继承中不能把它理解成固定指定“某个父亲”。

```python
class Sensor:
    def __init__(self, name):
        self.name = name

    def describe(self):
        return f"传感器 {self.name}"

class CalibratedSensor(Sensor):
    def __init__(self, name, offset):
        super().__init__(name)
        self.offset = offset

    def describe(self):
        return super().describe() + f"，偏移 {self.offset}"

device = CalibratedSensor("A", 0.5)
assert isinstance(device, Sensor)
assert device.describe() == "传感器 A，偏移 0.5"
```
构造 device 时先执行子类初始化，`super().__init__` 建立 name，再建立 offset；调用 describe 先进入子类，再明确复用基类说明。若子类写了自己的初始化却不调用所需基类初始化，基类状态不会自动补齐。`isinstance` 检查实例与类/基类关系，`issubclass` 检查类之间的继承关系；关系成立本身不证明子类保留业务契约。

这里的例子只演示单继承。多继承的方法解析顺序、描述符以及完整对象模型另属进阶专题。只想给对象增加日志或存储能力时，可把另一个对象作为属性组合进去，避免制造不成立的“是一种”关系。可对照 [Python 官方教程继承正文](https://docs.python.org/3/tutorial/classes.html#inheritance)。

## 方法、协议与多态
Python 常重视对象“能做什么”，例如可迭代对象只需满足迭代协议，不必继承某个具体业务父类。这种按行为合作的思路叫鸭子类型。__repr__ 提供调试表示，__len__ 支持 len，__iter__ 支持遍历；这些特殊方法应遵循对应协议，不要仅为了语法花哨而滥用。

对象设计仍需考虑测试：构造时避免自动联网或读取大量文件，让依赖可以传入。将核心计算与输入输出分离，能让对象在脚本、测试与界面中复用。本例为教学简化，add 还未验证 NaN 和绝对零度，实际项目应根据契约补齐。

## 通过职责判断是否建类
先列对象必须保持的状态，再列改变这些状态的合法操作。如果数据只进入函数、计算一次就返回，没有需要共同维护的长期状态，普通函数可能更清楚。如果多个操作需要共享同一组约束，类的价值就更明显。
继承层次应保持可替换性。例如子类方法若突然不再接受父类允许的输入，使用父类接口的调用者就可能失败。复用几行代码不足以证明存在合理继承关系，组合往往更容易控制变化。
对象也可能造成隐藏耦合：一个方法修改状态，另一个方法依赖调用顺序，却没有文档说明。可以让方法名表达副作用，提供明确初始化流程，并通过测试覆盖状态转换。面向对象的目标是让变化可理解，不是把所有名词都变成类。
