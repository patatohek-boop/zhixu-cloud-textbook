## 先说明什么叫“循环正确”
**前置条件**是开始时必须满足的输入约束；**后置条件**是结束时承诺的结果。

### 每轮保持什么

**循环不变量**是在每次检查循环条件时成立的关系；它并不要求变量数值不变。

### 怎样保证结束

**递减量**是每轮严格下降且不能无限下降的非负整数。先证明终止后结果正确，再证明一定终止，才能得到完整正确性。

## 重复不是复制粘贴
当同一规则要处理一组数据时，用循环明确表达“对每一项做什么”。`for` 遍历可迭代对象，适合已知数据集合；`while` 在条件成立时重复，适合迭代次数由计算过程决定的任务。

### 右端不包含的计数规则

`range(n)` 依次给出 0 到 n-1，右端不包含使长度恰好为 n。

### 先读懂 while 的一次循环

`while 条件:` 每次先检查条件；真则执行缩进块，假则退出。`k += 1` 等价于把 `k + 1` 重新绑定给 k；`total += values[k]` 把当前位置的整数加入累计和。下面 k 依次为 0、1、2，三轮后为 3，条件变假。代码中的 `k, total = 0, 0` 是两个名字分别初始化为零。

## 一个真正完整的循环证明
任务：对有限整数列表 `values` 求和，令 n 为其长度。
```python
values = [18, 20, 22]
k, total = 0, 0
while k < len(values):
    total += values[k]
    k += 1
assert total == sum(values)
```
不变量是 $0\le k\le n$ 且 $\mathrm{total}=\sum_{i=0}^{k-1}\mathrm{values}[i]$；空和规定为零。

1. **初始化：** k=0、total=0，等式成立。
2. **保持：** 若开始时 k<n，索引合法。加入第 k 项后再把 k 加一，total 恰好变成新的前 k 项之和。
3. **退出：** k≥n 与不变量 k≤n 合起来给出 k=n，故 total 是全部元素之和。
4. **终止：** n−k 是非负整数，每轮减少一，最多执行 n 轮。

通俗地说，每轮只多处理一项，账本始终记录“已经处理过的部分”。这比只试 [18,20,22] 更强：论证适用于所有满足前提的有限整数列表，忽略资源耗尽。

下文浮点平均示例采用同样状态结构，但一般浮点累加保存的是**逐次舍入后的和**，不保证等于精确实数和。其特定输入恰能精确表示；不应把整数证明无条件推广到任意浮点输入。

```python
values = [18.0, 20.0, 22.0]
total = 0.0
count = 0
for value in values:
    total += value
    count += 1
if count == 0:
    print("没有可计算的数据")
else:
    print(total / count)  # 20.0
```

在第一次循环前，total 是零。处理前 k 个数据之后，在本例可精确表示的数值中，total 等于这 k 个数之和；一般浮点输入对应逐次舍入后的累计值，count 恰好等于 k；这条每轮都保持成立的陈述叫循环不变量。最后 k 等于数据总数，所以 total/count 确实是算术平均。理解不变量，比单纯记住模板更容易发现“累加器放错位置”的问题。

对本例画三列表格：当前 value、更新后 total、更新后 count。三轮结果分别是 (18,18,1)、(20,38,2)、(22,60,3)。如果把 total=0 放进循环，每轮都会清空历史，最终只剩最后一个值。程序错误常来自状态在何处建立、何时更新，而不是某个加法算错。

while 循环还要说明终止理由。例如从 n=5 开始，每轮 n 减一，条件为 n>0，那么非负整数 n 严格下降，最终会到零。如果每轮错误地增加 n，条件将一直成立。真实数值迭代应同时设置容差与最大迭代次数，避免因浮点误差或不收敛无限运行。

## break、continue 与循环 else
`break` 立即离开最近一层循环；`continue` 跳过本轮剩余语句，进入下一轮。循环后的 else 在循环正常结束而未被 break 中断时执行，可用于表达“遍历完仍未找到”。它与 if 的 else 不同，初学时可以先用显式变量表达结果，再学习这种紧凑写法。

遍历列表时通常不要同时删除其中的元素，因为索引移动会导致跳过数据。可创建新列表，或遍历副本。嵌套循环的工作量相乘：外层 n 次、内层 m 次，主体通常执行 nm 次。输入增大一百倍，运行时间不一定只增大一百倍，算法结构决定扩展成本。

## 从循环表检查边界
计数任务最常见的错误是多一次或少一次。写下循环开始前、每轮开始、每轮结束和全部结束后的状态，确认索引始终在允许范围内。若处理长度为零或一的序列，很多隐藏假设会立刻暴露，所以它们应成为最早测试的例子。
累加和累乘的初始值不同：求和从零开始，因为加零不改变结果；求积从一开始，因为乘一不改变结果。寻找最小值时不要随意用零初始化，否则全为正数的输入会错误得到零；可从首元素开始并明确处理空输入。
对循环搜索，找到目标后是否停止取决于任务。找第一个匹配可中断，找全部匹配则应继续。把“找到没有”和“找到多少”混用，常导致看似正确的示例在重复数据上失败。始终先写清楚输出契约，再选择控制语句。

## 练习
1. `sum(range(1, 5))` 为何是 10 而不是 15？
<details><summary>查看解析</summary>range 的终点不包含，因此只包含 1、2、3、4，总和为 10。要包含 5，可使用 range(1, 6)。</details>

2. 若累计平均值时将 count 的初始化放入循环，会出现什么？
<details><summary>查看解析</summary>count 无法记录历史数量，最后通常只剩 1，导致总和被错误地除以 1。累加状态应在循环前建立。</details>
