## 从循环到表达式
推导式把“遍历—筛选—变换”写成一个结构清楚的表达式。`[x*x for x in values if x>0]` 的阅读顺序可以是：遍历 values，保留正数，然后计算平方。列表推导式立即生成完整列表，集合与字典也有相应写法。嵌套太深或同时处理许多分支时，普通循环往往更容易检查。

```python
values = [-2, -1, 0, 1, 2]
positive_squares = [x * x for x in values if x > 0]
print(positive_squares)  # [1, 4]

def running_total(numbers):
    total = 0
    for number in numbers:
        total += number
        yield total

stream = running_total([2, 3, 5])
print(next(stream))  # 2
print(list(stream))  # [5, 10]
print(list(stream))  # []
```

yield 暂停函数并交出一个值，下次请求时从暂停处继续。调用生成器函数时不会立即执行整个函数体，而是得到一个生成器对象。因此它适合大文件逐行处理或大型数列生成：无需一次将全部结果放进内存。

## 可迭代对象与迭代器
可迭代对象能提供迭代器，例如列表和字符串；迭代器记录当前遍历位置，并通过 next 提供下一项，耗尽时抛出 StopIteration。for 循环替你完成请求和结束处理。列表可以多次从头遍历，某一个生成器对象通常只能顺序消费一次。若需要重复遍历，应重新创建生成器，或明确转成列表并接受内存开销。

把生成器想成取号窗口比把它想成现成数组更合适：你每来一次领到下一个号码，领走的不会自动回到队首。sum、max、list 等函数都会消费它。调试时为了“看一眼”调用 list，可能已把后续计算需要的内容取完，因此应注意观察操作本身是否改变状态。

## 惰性不是免费
生成器节省中间结果内存，但每一步仍需计算，也不保证比列表更快。错误可能推迟到实际迭代时才出现，文件资源也可能需要一直保持打开。使用文件生成器时，要让消费过程发生在文件仍然打开的上下文中，避免返回一个依赖已关闭文件的惰性对象。

标准库 itertools 提供组合、分组、累计和切片等工具。使用无限迭代器必须有停止条件，例如限制取前十项。生成器表达式只需将方括号改为圆括号，但切勿仅因“更高级”就使用它；输入规模、是否重复访问、错误定位和可读性共同决定选择。

## 惰性流水线如何节省空间
设文件有很多行，每行先清理空白，再筛选有效记录，最后转换数值并累计。若每一步都创建完整列表，多个中间结果可能同时占据内存；生成器可以让一条记录依次经过各步骤，处理完再取下一条。
这种方式适合单向流动的数据，但不适合需要频繁回看任意位置的算法。若要排序全部记录，通常仍需收集数据或使用外部排序策略；惰性并不能消除任务本身的信息需求。
生成器函数中的异常只会在执行到相应位置时抛出，而不是创建生成器对象时立即出现。调用者需要把异常处理放在实际消费阶段。调试时可先用小型列表验证每一步，再切换到流式输入，减少状态与资源生命周期同时出现的复杂度。

## 练习
1. `g=(x*x for x in range(3)); sum(g); list(g)` 最后得到什么？

2. 读取十亿行文件做单次求和，应倾向列表还是逐行迭代？
