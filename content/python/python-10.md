## 三个经常混用的词
**可迭代对象**可以用 `iter(obj)` 获得迭代器；

### 迭代器记住进度

**迭代器**支持 `next(it)`，每次返回下一项，耗尽时抛 `StopIteration`，并且 `iter(it)` 返回它自身。列表是可迭代对象，但不是迭代器。

### 生成器保存暂停状态

**生成器**是由含 `yield` 的函数或生成器表达式产生的一类迭代器，会保存暂停处及局部状态。

列表推导式立即收集结果；生成器表达式按需计算结果。

### 创建时仍会发生的求值

惰性不意味着所有表达式都等到遍历才处理：生成器表达式最外层可迭代表达式在创建时就求值。通俗地说，领取窗口可以先开好，但下一份商品往往在轮到它时才制作。

## 按协议跟踪 yield
下文 `running_total([2,3,5])` 创建生成器时，循环体尚未运行。

### 从第一次请求到耗尽

第一次 `next` 初始化 total=0，读 2、累计后在 `yield` 暂停，交出 2。接着 `list` 从暂停处继续，依次读 3、5，得到 [5,10]；再调用 `list` 得到 []，因为该迭代器已经耗尽。

前 k 次产出后，不变量为 total 等于前 k 个输入的逐次累计结果。它与普通求和循环同源；不同的是每次暂停后局部状态仍被保存。重新从头遍历需要**重新调用生成器函数**，不是再次使用同一个已耗尽对象。若输入无限，全部转成 `list` 就不会自然结束，必须先限定取用数量。

## 从循环到表达式
推导式把“遍历—筛选—变换”写成一个结构清楚的表达式。`[x*x for x in values if x>0]` 的阅读顺序可以是：遍历 values，保留正数，然后计算平方。列表推导式立即生成完整列表，集合与字典也有相应写法。嵌套太深或同时处理许多分支时，普通循环往往更容易检查。

```python
values = [-2, -1, 0, 1, 2]
positive_squares = [x * x for x in values if x > 0]
print(positive_squares)  # [1, 4]

def running_total(numbers):
    total = 0
    for number in numbers:
        total += number
        yield total

stream = running_total([2, 3, 5])
print(next(stream))  # 2
print(list(stream))  # [5, 10]
print(list(stream))  # []
```

yield 暂停函数并交出一个值，下次请求时从暂停处继续。调用生成器函数时不会立即执行整个函数体，而是得到一个生成器对象。因此它适合大文件逐行处理或大型数列生成：无需一次将全部结果放进内存。

## 可迭代对象与迭代器
可迭代对象能提供迭代器，例如列表和字符串；迭代器记录当前遍历位置，并通过 next 提供下一项，耗尽时抛出 StopIteration。for 循环替你完成请求和结束处理。列表可以多次从头遍历，某一个生成器对象通常只能顺序消费一次。若需要重复遍历，应重新创建生成器，或明确转成列表并接受内存开销。

把生成器想成取号窗口比把它想成现成数组更合适：你每来一次领到下一个号码，领走的不会自动回到队首。sum、max、list 等函数都会消费它。调试时为了“看一眼”调用 list，可能已把后续计算需要的内容取完，因此应注意观察操作本身是否改变状态。

## 惰性不是免费
生成器节省中间结果内存，但每一步仍需计算，也不保证比列表更快。错误可能推迟到实际迭代时才出现，文件资源也可能需要一直保持打开。使用文件生成器时，要让消费过程发生在文件仍然打开的上下文中，避免返回一个依赖已关闭文件的惰性对象。

标准库 itertools 提供组合、分组、累计和切片等工具。使用无限迭代器必须有停止条件，例如限制取前十项。生成器表达式只需将方括号改为圆括号，但切勿仅因“更高级”就使用它；输入规模、是否重复访问、错误定位和可读性共同决定选择。

## 惰性流水线如何节省空间
设文件有很多行，每行先清理空白，再筛选有效记录，最后转换数值并累计。若每一步都创建完整列表，多个中间结果可能同时占据内存；生成器可以让一条记录依次经过各步骤，处理完再取下一条。
这种方式适合单向流动的数据，但不适合需要频繁回看任意位置的算法。若要排序全部记录，通常仍需收集数据或使用外部排序策略；惰性并不能消除任务本身的信息需求。
生成器函数中的异常只会在执行到相应位置时抛出，而不是创建生成器对象时立即出现。调用者需要把异常处理放在实际消费阶段。调试时可先用小型列表验证每一步，再切换到流式输入，减少状态与资源生命周期同时出现的复杂度。

## 从普通循环改写，再检查惰性

给定 `[3, -1, 0, 2]`，先用普通循环收集所有严格正数的平方，再改写为列表推导式。最后把同一规则写为生成器表达式：先取一次 `next`，再收集剩余项，分别预测结果。

<details><summary>参考实现与状态解释</summary>

```python
values = [3, -1, 0, 2]
by_loop = []
for value in values:
    if value > 0:
        by_loop.append(value ** 2)
by_comprehension = [value ** 2 for value in values if value > 0]
assert by_loop == by_comprehension == [9, 4]
stream = (value ** 2 for value in values if value > 0)
assert next(stream) == 9
assert list(stream) == [4]
assert list(stream) == []
```

推导式的读取顺序是“遍历每项→判断是否保留→计算平方”；生成器在第一次请求后已消费 9，后续收集从当前位置继续。空列表输入应生成空结果，不能无条件先取 `next`。
</details>

## 练习
1. `g=(x*x for x in range(3)); sum(g); list(g)` 最后得到什么？
<details><summary>查看解析</summary>得到空列表。sum 已经取走 0、1、4，生成器耗尽；再次迭代不会自动重启。</details>

2. 读取十亿行文件做单次求和，应倾向列表还是逐行迭代？
<details><summary>查看解析</summary>通常倾向逐行迭代，只保留累计状态，避免把全部文本装入内存。同时应处理异常行并明确文件编码。</details>
