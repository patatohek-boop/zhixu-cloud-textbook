## 从名字到文件内容还隔着什么
**路径**标识文件系统中的位置；**当前工作目录**是相对路径的起点；

### 文件对象与读取模式

**文件对象**是打开后用于读写和管理资源的运行时对象。路径存在不保证内容正确，也不保证下一刻仍存在。文本读取把字节按编码转为字符，二进制读取直接给出字节。

**上下文管理器**提供进入与退出协议。`with open(...) as handle` 成功进入后，退出代码块时会调用资源清理，包括因普通异常退出的情形；文件对象的退出处理会关闭文件而不会默认吞掉异常。

### 自动清理保证的边界

进程被强制终止、系统崩溃等情况不属于这项语言级保证。

## 用临时文件验证两条路径
```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as directory:
    path = Path(directory) / "example.txt"
    path.write_text("20\n", encoding="utf-8")
    try:
        with path.open(encoding="utf-8") as handle:
            assert handle.readline().strip() == "20"
            raise ValueError("模拟处理失败")
    except ValueError:
        pass
    assert handle.closed
```
通俗地说，`with` 把“借资源—使用—归还”绑在一起，但不替你证明读到的数字正确。失败仍需要上层处理；例中只为了展示关闭行为才捕获这个人为异常。

写模式 `w` 在打开成功时就可能截断已有文件，不是等 `write` 才覆盖。需要只新建时用 `x`。先检查存在再写不能消除并发竞争，重要文件应采用明确的创建或替换策略。

## 内存与磁盘的边界
变量存在于运行中的进程内，程序结束后通常消失；文件把数据保存在磁盘上，供下次读取。读取文件前应明确路径、编码、格式和大小。路径只是位置描述，文件可能不存在、权限不足，内容也可能与扩展名不符。稳健程序不会把“文件名看起来正确”当作内容正确的证明。

pathlib 用对象表达路径，`Path("data") / "measurements.txt"` 比手工拼接斜杠更容易跨平台使用。相对路径相对于当前工作目录，不一定相对于脚本目录。项目需要明确从哪里启动，或在脚本中根据文件位置构造资源路径；交互式环境不一定存在 __file__，因此不能机械照搬所有脚本写法。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

with TemporaryDirectory() as folder:
    path = Path(folder) / "temperatures.txt"
    path.write_text("20.0\n21.5\n19.5\n", encoding="utf-8")
    values = []
    with path.open("r", encoding="utf-8") as handle:
        for line in handle:
            stripped = line.strip()
            if stripped:
                values.append(float(stripped))
    print(sum(values) / len(values))  # 20.333333333333332
```

示例使用临时目录，退出后自动清理，便于独立运行而不覆盖已有文件。with 确保离开代码块时关闭文件，即使中途发生异常也会执行资源清理。逐行遍历适合较大的文本；read_text 一次读取全部内容，更适合小文件。选择方式应考虑数据规模，而不是习惯。

## 写入不是无风险动作
模式 r 表示读取，w 表示创建或截断后写入，a 表示追加，x 表示仅在文件不存在时创建。若需要避免覆盖，用 x 或先制定明确的输出命名规则。重要结果可先写临时文件，确认成功后再替换目标，减少写到一半留下损坏结果的风险；多进程共同写文件还需要进一步同步策略。

文本模式处理字符与编码，二进制模式处理字节。图片和压缩包不能当 UTF-8 文本直接读取。文件名含中文通常没有问题，但仍应明确编码；路径编码与文件内容编码是不同层次的问题。对于来自他人的路径，要限制操作在预期目录中，尤其是删除或覆盖时。

## 从异常记录定位数据问题
若第几行无法转为数值，应报告行号和原因，保留原始输入，避免悄悄丢弃异常行。空文件时 len(values)=0，不能直接除法；本例输入已知非空，实际函数应明确检查。文件操作的可靠性来自边界处理，而不是把全部异常都隐藏掉。

## 小文件与大文件的不同策略
本例把所有有效温度放进列表，适合初学和小数据。如果只需要平均，可以边读边保存计数与累计和，不必保留每个值；若还要中位数、排序或逐条追溯，存储策略就不同。计算目标决定需要保留哪些信息。
文件读取失败时，应区分路径错误、权限问题、编码不匹配与内容无效。它们对应不同修复方式，不应一律显示“没有数据”。对于长批处理，记录已完成部分与失败位置有助于恢复，但恢复规则需要避免重复处理。
写结果前先确认输出目录和文件名，重要项目可使用时间或版本标记。覆盖旧结果应是明确设计，不应由默认写入模式悄悄发生。
