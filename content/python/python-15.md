## 规格、测试用例与回归测试
**规格**是函数应满足的输入输出与失败契约；**测试用例**是一组具体输入及预期行为；**回归测试**检查已经修复的错误是否重现。通过有限样例不能推出所有输入都正确，除非输入空间确实有限且已穷尽，或结合了覆盖全部情况的证明。

例如错误函数 `return values[0]` 对 [5]、[5,5] 都给出正确均值，却对 [1,3] 返回 1 而非 2。因此测试数据要覆盖数值不同的情形，才能把正确均值算法与“只返回首项”的错误算法区分开。

## 均值的区间界及证明
对 n≥1 个有限实数 $x_i$，设最小值 a、最大值 b。逐项有 $a\le x_i\le b$，求和得 $na\le\sum_i x_i\le nb$，再除以正数 n，得到
$$a\le\bar x=\frac1n\sum_i x_i\le b.$$
这是对精确算术的证明，不是仅靠随机试几组得到的规律。浮点实现还要容许合理舍入，并排除 NaN、溢出等情况。性质成立也不足以证明函数就是均值：错误地永远返回最小值也满足区间性质，所以还需准确例题和其他契约检查。

测试时先划分非空有效输入、空输入、非法类型、非有限值等情况；只对函数承诺支持的输入要求正常返回，对违反契约的情况要求明确失败。后文最小均值程序的承诺范围是普通非空数值列表，不是完整的工业数据验证器。

## 均值函数的测试实现
测试不是证明程序“绝对没有错误”，而是把关键预期变成可重复的检查。有效测试应来自需求和边界，而不是逐句复述实现。摄氏度转开尔文可检查零点、常用值、最低允许值和非法输入；仅检查函数是否存在，不能证明计算正确。

### 先用函数、断言和异常完成三类检查

先运行下面版本；它只用到已经学过的语法。普通输入检验计算，单元素检验边界，空输入检验约定的失败。这里 `assert` 只用于开发测试，不代替函数中的输入检查。请用普通的 `python test_mean_basic.py` 运行，不加会删除断言的 `-O` 选项。

```python
import math

def mean(values):
    if not values:
        raise ValueError("至少需要一个数")
    return sum(values) / len(values)

assert math.isclose(mean([1, 2, 3]), 2.0)
assert mean([5]) == 5.0
try:
    mean([])
except ValueError:
    pass  # 收到约定异常，测试通过
else:
    raise AssertionError("空输入应当失败")
print("3 类检查通过")
```

### 扩展：把相同场景交给测试框架

下面保留 `unittest` 写法作为下一阶段版本。`class MeanTests(unittest.TestCase)` 建立测试类并继承框架行为，`self` 是当前测试实例，框架调用以 `test_` 开头的方法。类、继承和 self 将在[下一节](#/course/python/python-16)详细学习；初次阅读可先完成上面的基础版，学完类后回来逐行改写。`assertRaises` 是[文件与上下文管理](#/course/python/python-12)中所学上下文管理器的另一种用途：检查缩进块是否抛出指定异常。

```python
import unittest

def mean(values):
    if not values:
        raise ValueError("至少需要一个数")
    return sum(values) / len(values)

class MeanTests(unittest.TestCase):
    def test_regular(self):
        self.assertAlmostEqual(mean([1, 2, 3]), 2.0)

    def test_single(self):
        self.assertEqual(mean([5]), 5.0)

    def test_empty(self):
        with self.assertRaises(ValueError):
            mean([])

if __name__ == "__main__":
    unittest.main()
```

把代码保存为 test_mean.py 后用本机 Python 运行。正常结果、单元素边界和空输入契约各检查一次。浮点比较使用近似断言；异常测试确认失败是预期行为。测试通过意味着这些场景满足约定，不意味着未覆盖场景自动正确。

## 异常追踪与最小复现
traceback 通常从调用链显示到最终异常，先看最后一行的异常类型与信息，再定位自己代码中最相关的行。IndexError 提示索引越界，TypeError 提示操作与类型不匹配，NameError 提示名字查找失败。不要只修改报错行附近的语法，真正原因可能是更早的数据形状或状态发生变化。

最小复现是删掉与问题无关的代码和数据，保留仍能触发问题的最小例子。若一万行数据中仅一行出错，先保存该行与预期，再编写小测试。修复后保留回归测试，防止同一错误日后重现。

## 调试假设与测试层次
发现平均值不对时，可依次验证：数据是否读对、单位是否统一、累计是否重置、分母是否正确。每次只改变一个因素，并写下观察结果。随意同时修改很多行，会失去因果线索。不要为了让测试变绿而修改正确的预期值，先回到需求确认哪一边错了。

单元测试检查局部函数，集成测试检查组件连接，端到端测试检查完整流程。数值程序还可使用不变量，例如排序前后元素多重集合不变，非负数据平均值应落在最小值与最大值之间。这类性质能补充手工例子，但不能替代对前提条件的分析。

## 测试样例的区分能力
如果平均函数错误地只返回首元素，测试输入全相同仍会通过；使用不同数值才有机会揭示问题。如果排序函数只处理正数，单一正数样例也看不出来。好的样例应能区分合理实现与常见错误实现。
测试名称说明行为，失败信息指出预期与实际。一个测试尽量聚焦一个承诺，避免前面失败掩盖后面很多检查。输入数据应尽可能小，但保留触发边界的结构。
随机测试可以探索更多组合，但失败时应保存种子和具体输入，才能稳定复现。对浮点算法，容差来自问题尺度，不能为了让测试通过随意放宽。测试是可执行的规格说明，其价值取决于检查内容是否真正重要。
