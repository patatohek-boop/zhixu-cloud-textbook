## 用顺序表达意义
序列保留元素顺序，适合记录一天内依次测得的温度或一个点的坐标。列表用方括号表示，可以增删改；元组常用圆括号表示，外层结构不可变。元组并不意味着内部每个对象也不可变：一个包含列表的元组，其内部列表仍可修改。选择结构应依据数据含义，而不只是语法长短。

```python
temperatures = [21.0, 19.5, 23.0]
temperatures.append(20.0)
ordered = sorted(temperatures)
print(temperatures)  # [21.0, 19.5, 23.0, 20.0]
print(ordered)       # [19.5, 20.0, 21.0, 23.0]
for index, value in enumerate(temperatures, start=1):
    print(index, value)
point = (2.0, 3.0)
x, y = point
```

append 添加一个元素；extend 把另一可迭代对象中的各元素依次加入；二者处理列表参数时结果不同。pop 按位置移除并返回元素，remove 按值删除第一个匹配项。查找不存在的值和访问不存在的索引都可能报错，输入条件需要明确。

## 排序与原始顺序
`sorted(values)` 返回新的排序列表，原列表保持原样；`values.sort()` 就地修改并返回 None。写 `values = values.sort()` 会把名字绑定到 None，这是常见错误。排序时可提供 key，例如按字符串长度排序。Python 的排序是稳定的：关键字相等时，原来的相对顺序得以保留，这对多字段数据很有用。

enumerate 同时给出序号与元素，比手工维护索引更清楚。zip 将多个序列按位置配对，默认在最短者结束时停止；如果长度不一致意味着数据错误，应先检查长度或在支持的版本中使用 strict=True。不能让“能运行”掩盖数据被悄悄截断。

## 嵌套列表的共享陷阱
`rows = [[0] * 3] * 2` 并未创建两条独立的行，而是重复引用同一内部列表。修改 rows[0][0] 会影响另一行。正确建立独立行可用 `[[0 for _ in range(3)] for _ in range(2)]`。外层切片复制和 copy 也都只是浅复制；深层结构需要根据意图决定是否深复制，而不是机械地复制所有东西。

列表末尾追加通常效率较好，频繁在开头插入或移除需要移动后续元素。需要高效双端队列时可用 collections.deque。学习容器时，除了“能存什么”，还应询问“常做的操作是什么”，数据结构与算法是共同选择的。

## 序列切片与矩阵直觉
列表切片返回新的外层列表，因此修改切片本身的长度不会改变原列表；但切片元素若是可变对象，内部仍可能共享。把外层容器和内部元素分开画图，可以同时理解浅复制和嵌套列表陷阱。
元组常用来表达固定结构，例如横坐标与纵坐标，列表常用来表达可变数量的一类数据。这个区分是设计习惯，不是语法强制。若一条记录有很多字段，依靠位置记忆会变得脆弱，可考虑字典或数据类提供名字。
在数值计算中，二维列表并不会自动支持矩阵乘法，列表乘整数表示重复序列，而不是逐元素数乘。看到数学向量和 Python 列表长得相似，不应推断所有运算含义相同；后续 NumPy 数组提供了更明确的数值运算约定。

顺序和可变性都应写入接口约定。

## 练习
1. `a=[1,2]; a.append([3,4])` 的长度是多少？
<details><summary>查看解析</summary>长度为 3，最后一个元素是列表 [3,4]。若使用 extend([3,4])，长度才会变成 4。</details>

2. 为什么 `[[0]*2]*3` 不适合创建独立二维表格？
<details><summary>查看解析</summary>三个元素都引用同一个内部列表，改一行会影响其余行。应使用推导式分别创建每一行。</details>
