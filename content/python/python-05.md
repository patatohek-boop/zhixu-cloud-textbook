## 这一节先会判断一条分支

就绪检查：会[变量与类型](#/course/python/python-02)中的数值、布尔值和 `None`，能读懂 `<`、`<=`、`==` 的比较结果即可。先逐行跟踪本页温度例子，再检查 0、80、100 三个边界；不用先会函数或复杂容器。

第一遍把 `and`、`or` 用在比较结果上，理解“左侧已决定答案，右侧就不执行”。它们返回操作数而不总返回布尔值的规则是第二层。代码中的 `assert 条件` 表示“要求该条件为真，否则报错”，本页只借它检查结果，[测试](#/course/python/python-15)再系统学习。NaN 的详细检测、`match` 和把规则封装成函数都可后读；当前温度例子明确假设输入是有限数值，不用这些工具也能完成边界检查。

## 条件语句的精确定义
`if/elif/else` 从上到下检验条件，执行**第一个**为真的分支，余下分支跳过；若没有真条件，执行存在的 `else`。单独的多个 `if` 则各自判断。

### 布尔值与一般对象的真值

布尔值只有 `True`、`False`，但条件还允许其他对象按“真值规则”解释，例如空列表为假。真假不等于数据是否有效：温度零与缺失 `None` 都是假值，但含义不同。

`a and b` 先求 a；a 为假时直接返回 a，否则求并返回 b。`a or b` 先求 a；a 为真时直接返回 a，否则求并返回 b。因此它们并不总返回布尔对象。通俗地说，结果已由前半句确定，就不必冒险执行后半句。

## 用集合证明温度分支没有漏点
下文示例的有限实数温度 t 被分成 $t<0$、$0\le t<80$、$80\le t\le100$、$t>100$。这些区间两两不相交，并集是全部实数，所以每个有限实数恰有一个标签。

### 有限性是分类前提

这个结论**不包括 NaN**：NaN 与数值的大小比较均为假，会落入末尾分支。实际输入须先检查缺失、数值类型与有限性。

```python
numerator, denominator = 5, 0
allowed = denominator != 0 and numerator / denominator > 2
assert allowed is False  # 右侧除法未执行
assert (0 or 7) == 7
assert (3 and 9) == 9
```
本实验说明的是控制流，不是“把除零变成合法计算”。如果把检查写在除法之后，保护条件就失效。

## 把规则写成可执行决定
“温度太高就提醒”仍不够精确：多高算高，等于阈值怎么办，输入缺失怎么办？条件分支强迫我们回答这些问题。`if` 后的条件为真时执行缩进块，`elif` 只在前面的条件都不成立时继续检查，`else` 接住剩余情况。缩进属于语法，通常统一使用四个空格，不混用制表符。

比较符包括 `<`、`<=`、`>`、`>=`、`==`、`!=`。逻辑运算 `and` 要求两者都成立，`or` 只需至少一个成立，`not` 取反。用括号表达组合关系，即使不加也能运行，清晰仍然有价值。Python 支持 `0 <= temperature <= 100` 这样的链式比较，但不等于所有编程语言都支持它。

```python
temperature_c = 80
if temperature_c < 0:
    status = "低于本实验范围"
elif temperature_c < 80:
    status = "正常记录"
elif temperature_c <= 100:
    status = "高温，检查实验条件"
else:
    status = "超出本实验范围"
print(status)
```

80 不满足第二个条件，满足第三个条件，因此输出高温提示。要检查程序规则，应选择 -1、0、79.9、80、100、100.1 等边界附近数据，而不是只试 20。这里的“正常”只是教学实验的分类标签，不是适用于真实设备的安全判定。

## 短路求值的用途
`and` 在左侧为假时不再计算右侧，`or` 在左侧为真时不再计算右侧。例如 `denominator != 0 and numerator / denominator > 2` 可以避免在分母为零时做除法。先检查前提，再执行依赖前提的计算，这是一种可迁移的程序设计思路。

### 短路运算的返回值

不过 and、or 返回的可能是操作数本身，未必严格为 bool，初学时不要滥用它们代替清晰分支。

空列表、空字符串、零和 None 在条件中通常为假，但它们的含义并不相同。温度 0 是有效观测，None 才可能表示缺失；写 `if temperature:` 会把二者混在一起。检查缺失时应写 `temperature is None`。

## 从决策表验证完整性
先列输入范围和预期输出，再写代码，最后用表格逐项核对。多个独立 if 可能全部执行，if/elif 链通常只执行一个分支。如果一个样本可以同时属于多个标签，应使用独立判断或返回标签集合，不能强行套互斥分类。复杂结构匹配可进一步学习 match；基础数值判断使用 if 已足够清楚。

## 决策表比嵌套更容易审阅
把温度范围画成数轴，标出零、八十和一百，检查每个端点是否属于恰好一个区间。程序的分支顺序与区间覆盖应该对应：先满足的分支会阻止后续分支检查，因此把宽条件放在前面可能遮住更特殊的情况。
例如先判断温度小于等于一百，再判断温度小于零，后者永远无法在同一链中处理负数，因为前者已经接住了它。正确顺序不是固定从小到大，而是与条件包含关系一致。
对复杂业务可先将判断封装为返回分类的纯函数，再分别显示消息。这样规则能独立测试，也便于后来更改阈值。若规则随时间或设备类型变化，应把阈值作为参数或配置，不要在多个分支里复制同一个常数。
