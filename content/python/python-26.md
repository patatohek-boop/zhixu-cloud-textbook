## 版本控制与计算复现
**版本控制**记录可追踪的文件状态与变化历史；**依赖环境**包括解释器、库及其版本；

### 运行复现与重复实验

**可重复运行**指在规定输入与条件下重做同一计算；**科学重复实验**还会重新采样或测量，以检查结论对数据变化是否稳定。这些不是同一个承诺。

一次结果至少应关联源码版本、输入版本、参数、随机状态约定、依赖、运行入口和验证标准。相同源码在不同输入或依赖下可能给出不同结果；而重现一次计算，也不能说明结论对新的实验数据同样成立。

## 文件摘要与一致性
哈希把任意长度字节映射为固定长度摘要。密码学哈希使偶然或恶意找相同摘要通常很困难，但**不同内容理论上仍可能有同一摘要**，因此“摘要相同”是强一致性证据而非数学上的一一映射保证。

### 摘要不验证科学结论

更不能由它推出数据或算法正确。

反例：把有错误单位的 CSV 与永远输出零的程序都保存，并记录摘要；任何人都可复现同一个错误零值，所有摘要仍一致。由此可见，版本记录解决“用了什么”，测试和数学论证解决“实现是否符合契约”，实验设计解决“契约是否回答真实问题”。

本课程的核心掌握标准应是：能解释概念、预测执行、说明输入限制、构造反例，并独立完成小项目。描述符、元类、C 扩展、完整网络服务和分布式系统仍是后续专题，不能以看过名称算作已掌握。

## 项目目录与运行说明
一个月后的自己也是新的读者。可复现项目至少需要目标、输入数据说明、环境版本、运行命令、预期输出、限制和测试方法。README 是入口地图，代码是实现，测试是行为约定，示例数据是最小实验。把这些放在一起，学习成果才容易继续更新。

一个简单项目可包含 src、tests、data、outputs 和 README；小项目也可更简洁。

### 项目中的输入与产物

原始数据与生成结果应分开，不要覆盖唯一原始记录。文件名与变量名写明单位，数据字典写明一行代表什么。若数据含私人信息，使用合成或脱敏示例共享，不把敏感内容放进公开仓库。

## Git、提交与结果清单
Git 保存项目历史，提交应围绕一个可解释的改动，例如“为空输入增加明确错误”，而不是把很多无关变更混在一起。提交信息说明行为变化与原因。依赖目录、缓存、大型临时结果通常加入忽略规则；源码、文档、测试和小型示例应纳入管理。

### 工具与托管平台

GitHub 是托管与协作平台，不等同于 Git 本身。

```python
from pathlib import Path
import hashlib

text = "sensor,temp_c\nA,20\nA,22\n"
digest = hashlib.sha256(text.encode("utf-8")).hexdigest()
manifest = {
    "input_sha256": digest,
    "rows": 2,
    "temperature_unit": "degC",
    "analysis_version": "1.0"
}
for key, value in manifest.items():
    print(key, value)
```

哈希摘要可以帮助判断输入是否发生变化，但它不证明数据真实、合法或没有偏差。将输入摘要、程序版本和参数写入结果说明，可以追踪“这个数字究竟由哪次分析产生”。随机实验还应记录种子，数值结果必要时记录库版本与硬件环境。

## 依赖更新与结果核验
更新依赖、重构函数或调整算法后，先运行与变化有关的测试，再检查代表性结果。不要因为新结果更符合期待，就忽略与旧结果的差异。若计算定义发生变化，应更新文档与版本说明；若只是修复错误，应记录受影响结果，让读者知道哪些旧结论需要重算。

自动化工作流可以在提交后执行测试和生成文档，但自动化不替代内容审阅。公开教材尤其要保留公式前提、例题检验和来源链接。练习答案有修改时，应同时检查题目与测验，避免不同页面互相矛盾。

## 后续课程
本课程覆盖本科编程核心与科学计算入门。下一步可选择数据结构与算法、数值分析、软件测试、数据库、网络接口或机器学习。闭包与装饰器已有基础课文；描述符、元类、扩展模块和分布式系统仍是高级分支，本课只提供继续学习的入口，不声称已经精通全部 Python 生态。最有效的进阶方式是带着一个小问题，查官方文档，写最小实验，再整理成可复用笔记。

## 学习记录与维护说明
每次完成一章，记录一个原先误解、一个可运行例子和一个仍待解决的问题。日后修改答案时保留原因，比只收集最终正确代码更能帮助回顾思路。项目更新也应沿用这一习惯：说明改变了什么行为，为什么改变，以及怎样验证。
