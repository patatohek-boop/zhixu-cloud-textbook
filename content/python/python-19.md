## 先约定算法要返回什么
算法输入是一列按非降序排列、元素可一致比较的有限序列，长度为 n。任务是返回 target 第一次出现的索引，若不存在返回 `None`。允许重复、空序列和负数；不允许比较规则自相矛盾的数据。

### 复杂度采用的成本模型

这里以常数时间索引和比较为成本模型，分析比较次数，未把大整数位数成本藏进结论。

对非负函数 T(n)，$T(n)=O(g(n))$ 意味着存在常数 C>0 和整数 $n_0$，使所有 $n\ge n_0$ 有 $T(n)\le Cg(n)$。

### 上界不等于耗时

它是渐近上界，不表示精确耗时，也不自动表示最坏、平均还是最好；这里分析**最坏比较次数**。

## 下文二分代码的完整不变量证明
循环始终保持 $0\le left\le right\le n$，并保持：索引小于 left 的元素都小于 target；索引大于等于 right 的元素都大于等于 target。

1. 初始 left=0、right=n，两侧空集合使条件成立。
2. mid 落在候选区间内。若 `values[mid] < target`，由已排序可知 mid 左侧也小于 target，故令 left=mid+1 安全；否则 mid 及其右侧均不小于 target，故令 right=mid 安全。
3. 区间长度是非负整数且每次严格缩小，因此终止。
4. 终止时 left=right，该位置是第一个不小于 target 的候选。若它在范围内且相等，则是第一次出现；否则全部元素均不等于 target。

每轮候选长度至多缩成约一半，k 轮后不超过 $n/2^k$ 的相应整数界，故比较次数为 $O(\log(n+1))$。通俗地说，每次都用排序信息排除一整段，绝不是随便猜中点。第 27 节继续给出递归归纳法和排序证明，补齐“找到算法”之后“为何正确”的训练。

## 算法是可说明的步骤
同一个问题往往有多种正确程序，成本却差很多。查找一个值时，逐个检查的线性查找最坏需要 n 次比较；若数据已经排序，二分查找每次排除一半候选，比较次数约为 $\log_2 n$。但排序本身也有成本，不能在只查一次小列表时忽略准备工作。

```python
def binary_search(values, target):
    left, right = 0, len(values)
    while left < right:
        mid = (left + right) // 2
        if values[mid] < target:
            left = mid + 1
        else:
            right = mid
    if left < len(values) and values[left] == target:
        return left
    return None

print(binary_search([1, 3, 3, 7, 9], 3))  # 1
print(binary_search([1, 3, 7], 2))         # None
```

这里 [left,right) 表示尚未判定的元素区间；待求的最左插入位置可以位于闭区间 [left,right]，包括右边界。真正保持的是：left 左侧所有元素小于 target，right 及其右侧所有元素大于等于 target。结束时 left=right 得到插入位置，再检查该位置是否确有 target。

例如在 [1,3,3,7,9] 查找 3，right 依次变为 2、1；当区间是 [0,1) 时，答案索引 1 已在右边界。因此不能声称答案始终是半开区间内部的一个元素。每轮区间长度严格缩小，因此终止。此实现返回目标第一次出现的位置，前提是输入按非降序排列。若没有说明“已排序”的前提，就不能声称它适用于任意列表。

## 大 O 表达增长趋势
$O(n)$、$O(n\log n)$、$O(n^2)$ 描述规模很大时的增长上界，忽略固定常数和较低阶项。它不是某台电脑上的秒数，也不是“n 小时哪个一定快”的判据。嵌套两层各遍历 n 次的循环通常为平方量级，但若内层范围变化，需要真正计算执行次数。

空间成本同样重要。复制 n 个元素需要与 n 成正比的额外存储；生成器可能只保存少量状态，但若最终把所有结果转成列表，节省便消失了。优化应先定位实际瓶颈，再考虑算法、数据结构和实现细节。

## 递归把问题拆成更小问题
阶乘可以写成 $n!=n(n-1)!$，基本情况为 $0!=1$。递归需要基本情况、规模缩小和结果组合三部分。没有基本情况会不断调用；输入负数而没有验证，也可能永远接近不了零。

### 数学递归与执行栈限制

Python 不为普通递归保证尾调用优化，过深递归会遇到限制，所以遍历长序列往往更适合循环。

记忆化缓存可以避免重复计算相同子问题，但会使用内存，并要求输入与函数行为适合缓存。不要缓存依赖不断变化外部状态的结果而不制定失效规则。理解复杂度的目标是预测规模变化，而不是背诵算法名称。

## 用增长实验验证直觉
可让输入规模依次增加一倍，测量代表性运行时间。如果算法为平方量级，规模足够大且其他条件稳定时，耗时可能接近四倍；线性算法可能接近两倍。实际测量还受缓存、系统调度和固定开销影响，所以应重复并报告分布。
二分查找的边界设计值得手算空列表、单元素、目标小于最小值、目标大于最大值和重复值。每个例子都检查区间是否缩小，以及返回位置是否符合“第一次出现”的约定。
递归函数也可用同样方法：先验证基本情况，再验证一步如何把问题缩小。若递归分支重复求相同子问题，画调用树可直观看到指数增长。算法分析的意义是提前识别这种增长，而不是等程序卡住才增加硬件。
